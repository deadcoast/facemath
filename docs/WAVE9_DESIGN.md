# Wave 09 · The acquisition category must be reproducible from source pixels

## Priority and parent

The actual Wave 08 archive was extracted, its recorded SHA-256 verified, and its complete inherited suite executed before changes: 691 passed, one live-observer integration skipped. The native package remains absent and the attempted model download failed. This wave does not substitute a synthetic observer for a real-landmark validation claim.

Wave 08 deployed category-specific uncertainty but accepted operator category declarations. Wave 09 adds a measurable source contract to that same path: stored source pixels, declared apertures, frozen group reducers and simultaneous rules determine the category before observation. It is not another face analyzer, a universal quality score, a face recognizer or a hidden-distribution-shift detector.

## One computation owns routing

`AcquisitionPolicy` owns a strictly serialized measurement recipe and rule inventory. `ApertureSource` owns immutable RGB bytes, the exact half-open source rectangle and declared lineages. `MeasuredGroup` measures all members, retains exact analysis patches and coefficients, and derives a category without access to predictions or reference coordinates.

The existing `RoutingPolicy` embeds the measurement policy. The existing study freezer derives each group's category and stores the complete proof in its lock. The existing runner still attempts all eligible sources, including sources whose measured category will withhold deployment. Qualification uses the existing source-coordinate errors, joint-development fit and category-local calibration. A new measured-policy wrapper is NOT a separately fitted error model.

At pair analysis the original source-group rasters are loaded and remeasured before native model initialization or `observe()`. Their exact image/group/lineage inventories authorize the existing category radius. `BoundStratifiedCalibration` binds the two recomputed group digests to the observations; `FacialInstrument` passes the same qA/qB through its existing error sets, CanonicalState and intrinsic relation graph. The selected face's observation and all its raw geometry remain unchanged.

## Apertures and group membership are declared, not discovered

An aperture is integer `(x0,y0,x1,y1)` in stored-raster coordinates, half-open, within bounds and at least 4 by 4. Omission means the full stored raster. The instrument never clips, automatically crops, rotates EXIF display coordinates, searches for a favorable face box, or uses labels/predictions to choose an aperture. A declared region may be wrong or contain no face; the report shows the actual image and rectangle.

Group extrema include every declared enrolled member, including prospectively excluded observation cases. Exclusions remain excluded from native inference and accuracy denominators under the existing protocol, but cannot quietly delete a difficult frame from the measurement inventory. A repeated group containing clear and smooth source pixels gets the rule determined by the full extrema, not whichever source is selected for comparison. Its maximum member count is identical in the observation-enrollment contract and measurement policy.

Original pixels prove what this calculation consumed, not who selected an aperture, whether every real-world repeat was disclosed, or when a curator made a choice. New group IDs cannot prove independence. Source hashes do not establish external authorship or an authentic acquisition timestamp.

## Routing is a frozen conjunction, not a priority list

Every rule evaluates its complete predicate conjunction against the same min/max feature table. One match selects its category. No match is `__unmatched__`; multiple matches are `__ambiguous__`. Neither borrows a pooled radius. A user rule can itself forbid deployment. No comparison operator, feature, or code expression can be injected; only four comparisons over the named aggregate inventory are supported.

Rule-rejected categories retain their study errors and calibration scores, even when many groups exist. `deployment_permitted=False` makes their radius unavailable; sufficient sample size does not override the source contract. Rule permission and finite cohort support are separate states.

A standalone measured group is a diagnostic with original PNGs, feature arrays, exact analyzed grids, policy and predicate proof. It is not an observer result or calibration. Every load verifies bytes and recomputes all numerical features. A consistently rehashed false feature claim is rejected by that remeasurement.

## Query binding prevents a label-only shortcut

A measured calibration requires two raw `MeasuredGroup` objects. The selected pair image must be a member of its group. All context rasters and declared lineages are checked against every development/calibration category, not just the selected category. Caller-supplied group IDs, lineages or categories must exactly agree with the complete source group; omitted group/lineage fields can be derived from that evidence. Same-group declarations with different measured inventories are rejected.

A serialized bound calibration contains a claim about measured-group digests, not the pixels themselves. It cannot answer `source_quantile()` or authorize geometry until the pixels are restored and validated. Pair bundles store flat prefixed PNG/JSON/NPZ sidecars under the existing manifest and load them during verification and replay. The source images are not discarded after converting them to a category string.

The calibrated query gate records its partial execution journal when it refuses a source. The CLI defers provider creation, so a source-contract refusal does not require a native model file or installed MediaPipe. This is separate from prospective studies: those still retain the prescribed observation attempts for all eligible conditions so failure accounting is not selected by success.

## The diagnostics do not measure human accuracy

The gradient/variance statistic is an explicit code-value signal measurement. Its sampling, resizing, floor and aperture are frozen. High-frequency noise can raise it. The executed negative control routes a random-noise raster as `pixel_clear`; it is therefore NOT a face-quality detector or a promise of usable anatomical detail. The word “clear” is merely the demonstration policy's category name.

The study also imposes an observer-error shift within unchanged pixel conditions. A deterministic source classifier cannot infer a change that leaves all its inputs unchanged. Those held-out failures remain in the reported denominator; no new rule, threshold, calibration radius or exclusion is selected after viewing them.

Category-conditional calibration still requires exchangeability of complete groups within the frozen measured category and comparable group construction. Measuring the category objectively does not prove that assumption. Neither a low radius nor an image-rule match is a similarity probability.

## Controls and defects exposed

- A uniform code-254 test caught floating-point grayscale accumulation dropping an inclusive upper-code boundary. The recipe now uses exact uint8 integer-weighted sums `(299 R + 587 G + 114 B)/255000`, with one division. The independent grid test uses that exact specified recipe; no tolerance was widened to hide the failure.
- A strict pair-file-inventory check initially replaced inherited detailed path/hash errors with a generic inventory error. Moving completeness checking after per-file validation preserves both protections and the established diagnostics.
- Browser rendering exposed a mobile CSS min-content overflow in the source/feature grid. Explicit zero-minimum grid tracks/items now keep the page within its viewport while table scroll remains local.
- The first full run retained two obsolete version assertions for 0.8.0. Only their release strings were updated to 0.9.0; inherited numerical assertions are unchanged.
- A new CLI test initially used a guessed error phrase; the actual unsupported-category exception occurred before the patched native constructor, as intended. The test now asserts the actual contract.

The release includes the original development test output rather than presenting the final passing run as the only execution that occurred.
